# 视觉探索记录 · 2026-10-24 → 10-25

这份文档记录我们在「让一台车（和一只桌面宠物）看见世界」这件事上，试过什么、量到了什么、
最后为什么改成现在这个设计。**结论都带数据**；推测都标了「推断」。

---

## 0. 一句话

> **像素不该直接进模型。** 把画面翻成句子（测到的 / 推出来的 / 看不见的分开说），
> 智能留给 LLM，机械留给基础设施——这是我们唯一活下来的一条路。

---

## 1. 起点：把 NoMaD 当「感知」用

硬件前提：推理服务器是 P104-100 8 GB（Pascal，sm_61，只有 fp32 实用吞吐）。
这条约束直接把 7–8 B 的导航 VLA（NaVILA / UniVLA / SpaceVLA）排除，于是选了 NoMaD
（官方权重 76,473,631 B，EfficientNet-b0 视觉编码 + 扩散头）。

**部署是成功的**：`/infer` p50 164–216 ms，约 6 Hz 闭环，速度钳制生效，权重 `missing_keys=0`。

### 但把它当「世界理解」用，实测三宗罪

| 现象 | 数据 | 含义 |
|---|---|---|
| 速度恒饱和 | 每一帧 `v` 都被钳到上限 0.08 m/s | NoMaD 的 PD 假设 locobot 级速度（2–7 m/s），本车限速让它**永远顶格**，这一维不携带信息 |
| 距离不可信 | 车静止、goal 固定，`dist_pred` 仍单调增（1.15 → 2.34；另一次 12.43 → 10.50） | 帧间差异（人走动/噪声）被读成「离目标变远」；它是**它自己的读数**，不是测距 |
| 转向易翻面 | 同一机位相隔 53 s：`w = −0.400`（满舵右）→ `w = +0.303`（左），车一米没动 | 它响应的是「这一帧像该往哪偏」，不是「我在哪」 |

另外：**语言条件从未落地**。发布版只支持 goal-image，官方没发语言条件权重；「语言目标」
只能靠外部 LLM 从目标帧库里挑一张图来近似——那是另一个系统在工作。

**结论**：NoMaD 是一个**便宜的转向先验**。它值这个价，也只值这个价。

## 2. 转折：把「看」变成「读」

Minecraft World（Cortico 内建）给了范本：

> 观察 = 结构化文本，动作 = 异步执行器，节奏 = 实时（World 内节流 + 不经 LLM 的自保反射）

它能在协议层拿到干净世界，相机不行。所以移植的第一件事不是换模型，而是**把诚实认识论搬进措辞**：

四条硬规则：

1. **事实三分**：`测到`（框/计数/像素高度）、`推断`（朝向/手势/距离，附假设）、`影子提案`（永不驱动）、
   `看不见`（结构性盲区）。四类混写一次，后面所有结论都不可信。
2. **观察层不输出控制量**：schema 里没有 `v`/`ω`；想动，走动作层。
3. **看不见要说清**：视野外 / 被遮挡 / 过曝 / 掉帧 / 太远——五种分开，合并成「未知」就是撒谎。
4. **陈旧要标记**：任何一条观察都带「多少毫秒前」，超过阈值直接写「已陈旧，别当现在用」。

实际输出长这样（真帧，`zidane.jpg`，1280×720）：

```
【眼睛】12:38:06 的画面（630 毫秒前）
画面 1280×720，亮度正常；画面基本静止（运动能量 0.03）。
测到：person×2、tie×1。person（画面右）；person（画面中）；tie（画面中）。
人 2 个，最近的约 3.9 米（估）；朝向以「正面」为主（推断：鼻偏离肩中线；鼻在肩中线上方）。
推断的假设：人高按 1.7 m、焦距按 1280 px 推算；距离是估值。
画面里有 2 张脸能被认出来（正脸检测）。
提案（影子，不驱动）：前方 0.94 米、左 -0.15 米；0.08 米/秒、右转 0.40 弧度/秒；240 毫秒前算的。
看不到：身后 180°、身体两侧、以及被挡住的东西——相机只有一只眼睛。
```

## 3. 感知栈怎么落地（离线、无云依赖）

| 能力 | 实现 | 说明 |
|---|---|---|
| 检测 | YOLO11n (`yolo11n.pt`) | 5.35 MB，CPU 221 ms / 1280×720 |
| 姿态 | YOLO11n-pose (`yolo11n-pose.pt`) | 5.97 MB，17 个 COCO 关键点，160 ms |
| 人脸 | OpenCV Haar 正脸级联 | 自带于 opencv，缩到 640 宽后 177 ms（原图 1.6 s） |
| 提案 | NoMaD（远端） | 198–216 ms |

### MediaPipe 的坑（值得记下来）

- `mediapipe 0.10.33` 的 wheel **既没有 `solutions` 也自带 0 个 `.tflite/.task`**；
- Tasks API 需要的 `pose_landmarker.task` 托管在 `storage.googleapis.com`，本机不通；
- 所以姿态改用 **YOLO11-pose**（同为 17 关键点，且与检测共用一套 ultralytics）。
  代码里仍留 `--mediapipe-model <path>` 入口：拿到 `.task` 即可切换，转译层不用改。

### 权重的获取通道（现实约束）

- `huggingface.co`、`hf-mirror.com` 本机**超时**；
- **ModelScope 通**（400–560 ms）；`yolo11n-pose.pt` 从 `Ultralytics/YOLO11` 取，
  **6,255,593 B 与 Content-Length 逐字节相等**（本仓库 `models/` 里就是这份）。

## 4. 画面从哪来：两条路线的取舍

| 路线 | 优点 | 代价 |
|---|---|---|
| **浏览器 `getUserMedia`**（本包默认） | 零原生依赖，任何笔记本可跑；帧只在内存过一圈 | 权限/设备名/被占用等坑；**面板不开就没有画面** |
| **服务端直取 MJPEG**（机器人那条） | 稳定、与面板解耦，实测 40 KB/帧、可直接 `cam_look` | 需要相机可路由；独占会话 |

我们两条都留着：扩展默认走浏览器，`vision.perceptionUrl` 决定分析在哪做。
下一步若要做「不开面板也有画面」，就把 source 换成服务端拉流——接口位置已经留好。

## 5. 会话毒化：一条消息形状能毁掉整份对话

这是与视觉无关、但被同一批实验反复咬到的坑，一并记在这里：

- DSH 的 `followup()` / `inject()` 若传入**缺 `id`/`role`** 的草稿，会写出不合法的
  `user/message`；加载器校验整份日志，**一条坏事件就让整段对话打不开**。
- 真实事故：两份会话分别有 **65 条 / 58 条** 这样的坏事件（`session event at seq N lacks an
  identified message`），已按「补 UUID + role:'user'」修复并留备份。
- 现在的做法是三级兜底（照抄 `coopanion-connector-dsh` 的教训）：
  1. DSH 自己的 `createUserMessage()`；
  2. 用本会话最后一条真实 `user/message` 当模板（只借形状，`id` 换新）；
  3. 手写 `{ id, role:'user', content, source }`。
  另外：**复用 id 会把两条消息并成一条**，所以每次都必须新 UUID。

## 7. 还没解决

- 浏览器摄像头在开发机上**仍未跑通**（权限/设备未定性）；真视频流只验证到「测试图」。
- 面板 ↔ World 的帧上行只在假宿主里验证过，没在真 Cortico 里跑满。
- NoMaD 的 `dist_pred` 仍是「它自己的读数」，不参与任何决策。
- 姿态距离估计用的是「人高 1.7 m + 焦距 1280 px」的粗假设；要真用它，得先用已知距离标定一次。

## 8. 复现

```bash
pip install ultralytics opencv-python pillow          # 感知依赖
python tools/perception_sidecar.py --port 9402        # 起旁证服务
node ../../node_modules/tsx/dist/cli.mjs tools/demo-translate.ts <图片>
```

`tools/demo-translate.ts` 会 POST 一张图给 sidecar，再把回执喂给 `src/translate.ts`，
打印那段中文——整条「像素 → 句子」的链路，不依赖 Cortico、不依赖网络。
